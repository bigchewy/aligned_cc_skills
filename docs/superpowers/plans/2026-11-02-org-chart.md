# Org Chart Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove 13 advisors from the plugin (moving 4 to other repos), rename Wise Eric to Coach Eric, then ship B2B and B2C org chart pages built from one seats file and opened with `/aligned:org-chart`.

**Architecture:** `skills/org-chart/seats.yaml` plus the two registries feed `scripts/generate-org-chart.py`, which validates the data, fills templates in `scripts/org-chart-templates/`, and writes static pages to `skills/org-chart/pages/` (shipped) and an author page to `docs/plans/org-chart-coverage.html` (git-ignored). The pre-commit hook reruns the build when its inputs are staged.

**Tech Stack:** Python 3 with PyYAML (standard library otherwise), plain HTML/CSS/JS pages, pytest in `e2e/tests/`.

**Spec:** `docs/superpowers/specs/2026-11-02-org-chart-design.md`. Design page: https://claude.ai/artifact/2tQqAS6Tefirj9tgbzZGrY

## Global Constraints

- Run tests with `e2e/.venv/bin/pytest` and scripts with `e2e/.venv/bin/python` (system `python3` has no PyYAML on this machine). In a worktree, use the main checkout's venv: `/Users/ericpage/software/aligned_cc_skills/e2e/.venv/bin/...`.
- Never bump the plugin version by hand; the pre-commit hook does it. Never hard-code the next version in a test.
- No em dashes or en dashes in any text a client reads (seat pages, chart pages, SKILL.md user-facing lines). Registry text that contains them is converted to ", " at render time.
- Seat names and every file under `skills/org-chart/` must not match, ignoring case: `the-qa-engineer|QA Engineer`, `seo-expert|SEO Expert`, `the-designer`, `the-pm`, `the-devex-engineer`, `the-security-reviewer` (copy the exact patterns from the six `test_*_replaces_*` / `test_devex_engineer_retired.py` files).
- Pages open from `file://`: relative links only, no network script, Google Fonts allowed with system fallbacks.
- The build writes no timestamps. Output is byte-identical across runs on the same input.
- Coach Eric summary, verbatim: `CEO coach who pairs conscious leadership with systems thinking; finds the root cause, then the next step`
- One command per Bash call; use `git -C <dir>`; commit messages with `-m`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Starting seat mapping (seats, jobs text, missing text, advisor and framework placement) is in `/private/tmp/claude-501/-Users-ericpage-software-aligned-cc-skills/2cc08f02-f354-4e3f-97e5-652adef28262/scratchpad/map.js`. It predates the cleanup; apply the changes in Task 4.

## Review Focus

1. A framework or advisor added to a registry later with no seat: the build must fail with its id named, not render a chart that silently omits it. (Task 4 test `test_unplaced_framework_fails`.)
2. A seat on both charts: its page must show both headcounts and link back to both charts. (Task 5 test `test_shared_seat_links_both_charts`.)
3. Registry text containing `<`, `&`, or quotes (e.g. Pain + Reflection, Teach-Tailor-Take Control (TTTC)): must be HTML-escaped. (Task 5 test `test_registry_text_is_escaped`.)
4. A client opening the pages with no network: links and layout work with system fonts. (Task 5 test `test_no_network_scripts`.)
5. The pre-commit hook on a machine without PyYAML: commit still goes through with a warning. (Task 6 test `test_hook_tolerates_missing_python`.)
