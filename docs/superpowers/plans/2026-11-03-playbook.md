# Playbook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put every framework on an I / We / It map with areas and start-here picks, link every document to the framework that writes it, tag stage and market, remove `category`, and build the playbook pages plus the data for the link review page.

**Architecture:** `skills/playbook/layers.yaml` lists framework ids under areas, the way `skills/org-chart/seats.yaml` does. The registry gains `stages`, `market` and `{doc, from}` document entries and loses `category` and `follow_on_frameworks`. `scripts/generate-playbook.py` validates both files and builds `skills/playbook/pages/`, copying the shape of `scripts/generate-org-chart.py` (load_and_validate, build, check, write, `--check`). The pre-commit hook rebuilds the pages.

**Tech Stack:** Python 3 + PyYAML, pytest in `e2e/tests/`, static HTML/CSS with a little inline JS, bash hook.

**Spec:** `docs/superpowers/specs/2026-11-02-playbook-design.md`

## Global Constraints

- Run tests with `/Users/ericpage/software/aligned_cc_skills/e2e/.venv/bin/python -m pytest` (the worktree has no venv of its own).
- Never bump the plugin version by hand. The pre-commit hook does it. Never hard-code the next version in a test.
- One command per Bash call. No `|`, `&&`, `;` or `$()`. Use `git -C <dir>`.
- Commit messages use `-m`, never a heredoc, and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Stages are exactly `idea`, `pilot`, `nail-it`, `scale-it`, `milk-it`. Market is exactly `b2b` or `b2c`. Left off means any stage or both markets.
- `from` is a registry framework id, a list of ids, or the word `outside`.
- Confidence is exactly `sure`, `likely` or `guess`.
- The line at the end of every It framework page is exactly: `Put the result into your Top Goal or your next check-in.`
- The pages open from a local file. Links are relative. No script loads from the network. Fonts may load from Google Fonts, as the org chart does.
- Tokens come from `scripts/org-chart-templates/style.css`. The repo has no design-principles file.
- Portability rule (`CLAUDE.md`): every shipped step works for any user who installs the plugin.
- `prompt.md` frontmatter keeps plain document-name lists; only the registry gets `{doc, from}`.
- Arrows are drawn only into It frameworks. A framework in It and another layer counts as It. No arrow points into a We or I framework.

- Test: `e2e/tests/test_playbook.py` (links part), `e2e/tests/test_link_review.py` (file part)

**Interfaces:**
- Produces in `generate-playbook.py`: `doc_links(entry) -> list[dict]` returning `{"doc": str, "from": list[str], "kind": "required"|"helpful"}`; a plain string becomes `from: ["outside"]`; a single id becomes a one-item list.
- Produces: `check_links(registry: dict) -> list[str]` covering: every `from` valid; no framework lists itself; no loop through required links; the market rule below.
- Produces: `outside_required(registry) -> list[tuple[str, str]]` (framework id, doc).
- Review entry format, exactly:

```yaml
- id: sales-pitch-structure/positioning-statement
  framework: sales-pitch-structure
  doc: positioning statement
  kind: required
  from: 5-components-positioning
  confidence: sure
  reason: 5 Components writes the positioning statement as its output.
```

`id` is `<framework>/<doc slugified: lowercase, non-alphanumerics to single dashes>`. `from` copies the registry value.

- Confidence: **sure** when the writing framework names this document as its output in its purpose or prompt; **likely** when one framework fits but names its output differently; **guess** when more than one could write it, or none clearly does and you chose `outside`.
- `mochary-weekly-check-in` and `chj-operating-review`: the quarterly goals / OKRs document gets `from: proximate-objectives`.
- Market rule: a framework with a `market` that writes documents for at least one other framework must feed at least one framework whose `market` is the same or absent. The real registry must pass.
