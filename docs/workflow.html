Brainstorm

Explore the idea, question assumptions, design the approach, generate mockups, and critique everything before writing a single line of code.

▾
  • Project scan sub-agent — surveys structure, git history, patterns, tech stack
  • Understand the idea — one question at a time, no rush
  • Architect auto-consult — technical options vetted against codebase before presenting
  • Explore 2–3 approaches — trade-offs for each, lead with architect-recommended
  • Present the design — 200–300 word sections, clear structure
  • Generate visualization — mandatory: mockup, flowchart, and/or architecture diagram auto-selected
  • Write design doc — saved to docs/plans/
  • Multi-critic review — 1–4 critics auto-selected from advisor pool, with division of labor
  • Critique round 2 — only if medium/high severity issues found
  • Create git worktree — isolated workspace for implementation

Plan

Convert the design into bite-sized, TDD-focused tasks with exact file paths, code snippets, and test specifications. Every task is 2–5 minutes of work. Outputs two execution options: interactive or Ralph Loop.

▾
  • Research the codebase — read architecture docs, grep for patterns
  • Write tasks in small steps — test file first, then implementation
  • Verify every file path & snippet — no hallucinated references
  • No manual steps mid-sequence — Ralph Loop can't pause for humans
  • Add decision log — document architectural choices
  • Dual-critic review — Architect + Verifier agents in parallel
  • Critique round 2 — if issues found
  • Save plan to main branch — commit to docs/plans/ on main
  • Recommend execution mode — interactive for ≤10 tasks, Ralph Loop for >10

/aligned:executing-plans

Execute

Load the plan and implement it task-by-task, running tests after each. Batches of 5 tasks with review checkpoints. For larger plans, the Ralph Loop keeps context fresh.

▾
  • Load plan from main worktree
  • Implement in batches of 5 — TDD: test first, then code
  • Run verifications per task
  • Check LLM surface changes — auto-trigger evals if prompts changed
  • Report & wait for review — user approves before next batch
  • Log out-of-scope bugs — to Kanban board, no detours
Sub-skills invoked
test-driven-development eval-audit eval-failure-triage systematic-debugging
or
Alternative execution mode
Ralph Loop
while :; do claude -p "$(cat docs/ralph_loops/EXECUTE-PLAN.md)" ; done

Runs Claude in a bash loop — one task per iteration, then exits. Fresh context every time, no quality drift from window bloat. Each iteration reads the plan, finds the next un-checked task, implements it with TDD, marks it ✓, commits, and exits. The loop restarts for the next task. Writes a .ralph-done sentinel when all tasks are complete.

Finish

Verify everything works, scan for code simplification opportunities, then merge, PR, or keep the branch. Archive the plan and clean up the worktree.

▾
  • Deployment platform audit — file system access, env vars, dynamic requires, native deps
  • Run full test suite — hard stop if failing
  • Run production build — hard stop if failing
  • LLM eval — if prompt/surface files changed
  • Update architecture docs — if architecture changed
  • Code simplification scan — code-simplifier agent reviews branch diff
  • Present 4 options — merge locally, deploy + smoke test, keep, or discard
  • Execute chosen option — deploy option includes Vercel MCP + Playwright smoke tests
  • Archive plan to completed/
  • Cleanup worktree

Iron Rules

  • Tests first. No production code without a failing test.
  • Error paths too. Every mockResolvedValue needs a mockRejectedValue test.
  • Verify before claiming. No "it works" without fresh evidence.
  • Root cause first. No fix without investigation. No symptom-patching.
  • Fresh agents for critique. Never self-review; always spawn a sub-agent.
  • Plans live on main. Committed to docs/plans/ on the main branch.
  • 3 strikes = rethink. If 3 fixes fail, question the architecture.
  • No detours. Out-of-scope bugs go to the Kanban board.
