Brainstorm

Explore the idea, question assumptions, design the approach, generate mockups, and critique everything before writing a single line of code or strategy doc.

▾
Five-mode router: The skill classifies your topic into one of five modes — software, business, research, authoring, or planning — and runs the matching process. Each ends with a multi-critic review from the advisor pool.
Software Mode
  • Project scan sub-agent — surveys structure, git history, patterns, tech stack
  • Understand the idea — one question at a time, no rush
  • Architect auto-consult — technical options vetted against codebase before presenting
  • Explore 2–3 approaches — trade-offs for each, lead with architect-recommended
  • Present the design — 200–300 word sections, clear structure
  • Generate visualization — mockup, flowchart, and/or architecture diagram auto-selected
  • Write design doc — saved to docs/plans/
  • Multi-critic review — 1–4 critics auto-selected from advisor pool, with division of labor
  • Create git worktree — isolated workspace for implementation
Business Mode
  • Goal clarification — converge on a specific objective
  • Problem identification — structured obstacle mapping
  • Root cause analysis — 5 Whys / First Principles to find leverage points
  • Solution design — constrained options with trade-offs and resource requirements
  • Multi-critic review — 2–4 advisors (e.g., Dunford, Rumelt, Walling)
Research Mode
  • Corpus survey — comparative review of literature, registries, or prior artifacts
  • Comparative synthesis — evidence map or ranked review
  • Skeptic Pass — challenge claims and surface gaps
  • Deliverable: research memo or KB artifact
Authoring Mode
  • Content sequencing — curriculum, prompts, exercise programs, chapter order
  • Optional Research sub-phase — file-mediated sub-agent fork for evidence base
  • Domain-advisor panel — voice and accuracy review
  • Deliverable: sequenced design doc
Planning Mode
  • Multi-feature portfolio sequencing — what to build, in what order
  • Strategy advisor consult — sequencing trade-offs and dependencies
  • Roadmap + spawn-list — feeds into writing-plans for individual builds

/aligned:writing-plans

Plan

Convert a brainstorm or spec into a TDD implementation plan with dual-critic review. Plans live on main and feed the Execute phase.

▾
  • Research the codebase — read architecture docs, grep for patterns
  • Write tasks in small steps — test file first, then implementation
  • Verify every file path & snippet — no hallucinated references
  • Add decision log — document architectural choices
  • Dual-critic review — Architect + Verifier agents in parallel
  • Critique round 2 — only if issues found
  • Manual-deploy artifact catalog — auto-flags Supabase migrations and env-var additions for Post-Automation section
  • Save plan to main branch — committed to docs/plans/ on main
Sub-skills invoked
Sub-agent: codebase research Sub-agent: Architect critic Sub-agent: Verifier critic
▾

/aligned:executing-plans

Execute

Implement the plan task-by-task in batches with TDD discipline and review checkpoints between batches.

▾
  • Load plan from main worktree
  • Implement in batches of 5 — TDD: test first, then code
  • Run verifications per task
  • Check LLM surface changes — auto-trigger evals if prompts changed
  • Report & wait for review — user approves before next batch
  • Log out-of-scope bugs — to Kanban board, no detours
Sub-skills invoked
eval-audit root-cause-analysis code-reviewer agent
▾

/aligned:finishing-a-development-branch

Finish

The manual merge/deploy decision point after either path. Verify everything works, scan for code simplification opportunities, then merge, PR, or keep the branch. Archive the plan and clean up the worktree.

▾
  • Manual-deploy evidence gate — hard-stops merge until catalog artifacts (migrations, env vars) are verified
  • Deployment platform audit — file system access, env vars, dynamic requires, native deps
  • Run full test suite — hard stop if failing
  • Run production build — hard stop if failing
  • LLM eval — if prompt/surface files changed
  • Update architecture docs — if architecture changed
  • Code simplification scan — code-simplifier agent reviews branch diff
  • Present 4 options — merge locally, deploy + smoke test, keep, or discard
  • Execute chosen option — deploy option includes Vercel MCP + Playwright smoke tests
  • Archive plan to completed/
  • Cleanup worktree

Iron Rules

  • Tests first. No production code without a failing test.
  • Error paths too. Every mockResolvedValue needs a mockRejectedValue test.
  • Verify before claiming. No "it works" without fresh evidence.
  • Root cause first. No fix without investigation. No symptom-patching.
  • Fresh agents for critique. Never self-review; always spawn a sub-agent.
  • Plans live on main. Committed to docs/plans/ on the main branch.
  • 3 strikes = rethink. If 3 fixes fail, question the architecture.
  • No detours. Out-of-scope bugs go to the Kanban board.
