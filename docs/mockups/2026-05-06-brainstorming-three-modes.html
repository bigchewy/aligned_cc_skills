Brainstorming — Three New Modes

Adding Research, Authoring, and Planning to the brainstorming skill

Survey across software/planted/docs/, obsidian/aligned/, obsidian/personal/ + Architect blast-radius review. Final design at docs/plans/2026-05-06-brainstorming-three-modes-design.md.

Why this, why now

A survey of ~60 design and decision docs across three vault locations surfaced three brainstorm shapes that fit neither Software nor Business mode. The personalized-program-variants-design.md doc is the canonical "awkward middle" — 70% of its brainstorm work was instrument review + ACT-theoretical sequencing + curatorial slot-by-slot authoring. Architect-led Software mode would have been wrong; the schema fell out of domain advisors' (Hayes, Loehr, Chapman, Seligman, Oreizy) decisions. There was no fitting mode.

Eric also surfaced a Planning shape — multi-feature builds too big for a single brainstorm session. No clean written artifact exists yet; he reports actively struggling without this mode.

Diagnosis & goal

The crux Content-led brainstorms (curriculum, framework prompts, exercise sequencing, instrument review) currently route to Software mode and recruit the wrong panel. The Architect leads when Hayes / Loehr / Sisney should. The Q&A flow asks "where does the state live?" when it should ask "what does this audience need to learn first?" The deliverable comes out as architecture when it should come out as sequenced curriculum.

Goal: Match brainstorm work to a panel and process whose lens fits the work — content-led brainstorms recruit domain experts and produce sequenced arrangements; research-led brainstorms recruit evidence-skeptics and produce comparisons; portfolio-planning brainstorms recruit strategy advisors and produce roadmaps + spawn-lists.

Success criteria (outcome, not activity):

  1. Panel composition test. In the first 5 content-led brainstorms after launch, count how many recruit Architect as co-lead. Target: 0.
  2. Output-shape test. Count Authoring brainstorms whose final deliverable is a code-shaped design doc rather than a content-shaped sequenced curriculum. Target: 0.
  3. Auto-route accuracy. ≥80% of awkward-middle docs auto-route correctly without disambiguation.

Hard constraints

  • Software and Business modes unchanged in observable behavior — except the SKILL.md mode-explanation block's "Other modes" line, the one approved cosmetic surface change.
  • No backward-incompatible changes to consumer skills (kickstart, writing-plans, finishing-a-development-branch, etc.).
  • Authoring's optional Research sub-phase runs as a sub-agent fork (NEW pattern, Mode-as-sub-flow) — recursion forbidden; project-scan reuse from parent.
  • Personal-vault relational/check-in artifacts are out of scope (Planted's Garden surface owns those).
  • Two named advisors are referenced but absent from registry — must add via /aligned:add-advisor: Cagan (Planning, preferred-when-available, not blocking — default panel = Christensen + Rumelt + Eric Ries is launch-ready) and Sisney (Authoring's PSIU-shaped brainstorms; non-PSIU brainstorms have full coverage without him).

Research

Survey a corpus, produce a comparative review, ranking, or evidence map.

Triggers
literature review, evidence map, comparative review, instrument selection, framework comparison, KB design, "what does the literature say"
Advisors
Domain experts (topic-routed) + Rumelt (cutting-fluff source-quality) + Architect (retargeted at literature/KB sources for evidence-trace verification). No new generic Skeptic advisor.
Output
docs/plans/YYYY-MM-DD-<topic>-research.md for plan-shape, or knowledge/<area>/README.md for KB-shape
Critique config
fact-check-mode: all-critics, criteria-assignment: no, aggregation: sub-agent
Next steps
Commit synthesis. No writing-plans follow-on. Optional: open follow-up Authoring/Software brainstorm with research as input.

Process

  1. Question scoping. What's the question? What corpus is in scope?
  2. Corpus scan. Surface candidates. Note coverage gaps.
  3. Comparative synthesis. Per candidate: construct fit, evidence quality, licensing/cost, validation status.
  4. Skeptic pass. Mode-internal instruction — selected critics adopt the role. Verify citations, check for missing counter-evidence, flag licensing claims.
  5. Ranking + decision memo. Recommended candidate(s), explicit caveats, open questions queue.

Authoring

Select and sequence content into a coherent arc with rationale per element + orphan list. Domain advisors lead; Architect = late audit only when a code/schema seam exists.

Triggers
curriculum, program design, sequence content, exercise sequencing, "what to teach in what order", rewrite for audience, voice migration
Advisors
Domain experts (Hayes, Loehr, Chapman, Seligman, Sisney, Brown, Mate, Linehan, Levine, Grubb — topic-routed). Architect for late audit if code seam exists.
Output
docs/plans/YYYY-MM-DD-<topic>-design.md (existing convention)
Critique config
fact-check-mode: division-of-labor, criteria-assignment: yes, aggregation: sub-agent
Next steps
Same as Software mode — /aligned:using-git-worktrees + /aligned:writing-plans, or autopilot.

Process

  1. Population & constraints. Who is this for? What's non-negotiable?
  2. Corpus scan. What existing content is in scope?
  3. Optional Research sub-phase. Sub-agent fork — see callout below.
  4. Arrangement. Sequence/group/tier the corpus with the domain-advisor panel.
  5. Orphan / residual catalog. Content that didn't fit. Open questions deferred.
  6. Architect audit (conditional). Only if code/schema seam exists.
Authoring → Research sub-agent contract File-mediated handoff. Authoring writes a question file to /tmp/brainstorm-context-{topic}/research-{slug}-question.md; sub-agent reads references/research-mini-protocol.md, writes synthesis to research-{slug}-synthesis.md with shape: ## Synthesis / ## Open Questions / ## Confidence; returns only "Synthesis written to {path}". Main context never sees the transcript. Authoring asks user before dispatching — no silent auto-launch.

Planning

Identify and prioritize a portfolio of work items, each spawning its own future brainstorm. Two artifacts: roadmap + portfolio spawn-list.

Triggers
roadmap, prioritization, portfolio, "what to build next", milestone, sequence features, multi-feature build, "too big for one brainstorm"
Advisors
Cagan as named lead (prereq: add via /aligned:add-advisor). Until then: Christensen + Rumelt + Eric Ries with one of {Bezos, Graham, Tan} based on topic. Architect for codebase-reality dependency check (late audit).
Output
docs/plans/YYYY-MM-DD-<topic>-roadmap.md (strategic frame) + -portfolio.md (spawn-list, kanban-shaped)
Critique config
fact-check-mode: division-of-labor, criteria-assignment: yes, aggregation: sub-agent
Next steps
Commit roadmap + portfolio. Per item: /aligned:brainstorming against the spawn brief — produces design doc, then /aligned:writing-plans.

Process

  1. Opportunity space & constraints. Goal, audience, time horizon, budget, capacity.
  2. Candidate inventory. What work items are on the table?
  3. Sizing & dependencies. Per candidate: rough size, dependencies, prerequisites, risks.
  4. Sequencing & rationale. Strategic order with explicit "why this before that."
  5. Spawn briefs per item. Structured entry (target_mode, status, size, prerequisites, why-now, brief, success criterion).

Signal sets

features, components, APIs, bugs, refactoring, architecture, implementation, code, testing, data models

Research new

Planning new

Disambiguation rules

Software vs Authoring If the deliverable is code that runs, Software. If the deliverable is content humans consume (curriculum, prompts, exercises) even when there's a code seam, Authoring. The variants-design canonical test: it had a runtime adapter (code) but the brainstorm work was 70% content sequencing → Authoring.
Authoring vs Research If the deliverable is an arrangement (sequence, registry, curriculum), Authoring. If the deliverable is an evidence map / ranked synthesis with no arrangement output, Research. Authoring includes Research as an optional sub-phase (sub-agent fork).
Business vs Planning If the work is diagnostic (why isn't X working), Business. If the work is generative portfolio sequencing (which N things should we build), Planning.

Error paths — five failure modes addressed

The QA Engineer's Round 1 critique surfaced five concrete failure modes the happy-path design didn't address. Each new mode file specifies the fallback for these.

1. Disambiguation refusal User picks "Other" or types free-form on the 5-way question. Router asks one follow-up: "Could you describe in one sentence what you want as the deliverable?" If still ambiguous, defaults to Software mode and notes the auto-fallback to the user.
2. Authoring → Research sub-agent fail/timeout Sub-agent crashes, returns no confirmation within 5 min, or returns confirmation but writes corrupt/empty file. Authoring surfaces failure with three options: skip / retry / retarget. No silent retries; no auto-fallback to inline research (would defeat context-window discipline).
3. Malformed synthesis file If any of ## Synthesis, ## Open Questions, ## Confidence is missing, or Confidence lacks a caveat, validation surfaces the issue with the same three options. Required before integration into Authoring's working context.
4. Spawn-brief malformed in portfolio.md Structured fields (target_mode, status, etc.) are documentation-only. If the brief paragraph omits mode-disambiguating keywords, normal signal detection misses and user gets the standard 5-way disambiguation question.
5. Cagan absent at runtime Planning mode checks for advisors/prompts/marty-cagan.md existence. If absent, silently uses default panel (Christensen + Rumelt + Eric Ries). Same convention for Sisney with PSIU-keyword topics in Authoring (one-time notice to user, then proceed).

Decision log

One mode vs three modes

Survey fork recommended one mode (7-vs-3 ratio of curatorial-dominant vs research-only docs). The override rests on an asymmetry the survey could not see: Planning-shape work happens mentally without producing artifacts, so the corpus had no evidence of it.

Choice: Three modes. Designing for an unwritten shape is an explicit bet that artifact-production lag is worse than design-in-the-abstract risk. §Error paths and §Tests required name what "wrong on first use" looks like. Research split rather than folded into Authoring because standalone artifacts (change-mgmt KB, supplement brief) have a distinct deliverable shape that folding would distort. Confidence: 0.75 (downgraded from 0.85 — bet against survey evidence, not aligned with it)

Name for the content-sequencing mode

User: "Curatorial is a wonky word." Considered: Curatorial, Authoring, Composition, Content Design, Curriculum, Editorial.

Choice: Authoring. Plainest verb for "decide what to teach, in what order, voice"; generalizes from program design to book chapters to framework prompts to Mochary re-voicing equally. Confidence: 0.9

Authoring → Research handoff: inline vs sub-agent fork

User explicit: "See if it's possible to do this research work as sub-agents when you're inside of Authoring." Goal: prevent context-window pollution.

Choice: File-mediated sub-agent dispatch (Architect refined from "fork" to "file-mediated"). Matches existing pattern at software.md:80-105. Sub-agent transcript never enters Authoring's main thread. Confidence: 0.9

Planning advisor pool

User selected only Marty Cagan from the menu (Christensen, Drucker were available; user did not select).

Choice: Cagan as named lead; Cagan is missing from registry — hard prereq. Until then: Christensen + Rumelt + Eric Ries default panel via dynamic critic selection. Confidence: 0.85

Planning output: single doc vs two artifacts vs HTML kanban

User: "Two artifacts (roadmap + portfolio spawn-list)." Each portfolio entry independently usable as brainstorm seed.

Choice: Two artifacts. Distinct from existing docs/kanban/ (small auto-found items). Confidence: 0.9

Skeptic role for Research mode

Considered: add new generic Skeptic advisor vs use existing critic roles.

Choice: Use existing — Rumelt + Architect retargeted, with mode-internal Skeptic Pass instruction. A nameless skeptic doesn't earn registry placement; named experts with grounded prompts (Rumelt's strategic-clarity lens, Architect's evidence-trace lens) cover the role. Confidence: 0.85

Personal vault scope

Choice: Out of scope. Mode-detection signals must explicitly not claim shirin_and_eric, check_ins, journaling-as-decision artifacts. Brainstorming stays a work-tool; Planted's Garden surface owns reflective work. Confidence: 0.95
