Manual-Deploy Artifact Detection

Plugin design — v1: Supabase migrations + env vars

RCA + three-layer fix: catalog in _shared/, writing-plans emits Post-Automation entries, finishing-a-development-branch hard-gates on pasted evidence.

What broke

Autopilot workflow (brainstorming → writing-plans → executing-plans → finishing-a-development-branch) shipped code that depended on 5 Supabase migrations never applied to prod. Tests mocked Supabase, build passed, Vercel deployed. A week later: infinite /login loop because middleware read a column that didn't exist. 30 minutes of debugging.

Root cause

No typed concept of "manual-deploy artifact" The plugin has no first-class notion of a file class whose creation in a diff deterministically implies a non-automatable production step. Without the concept: nothing to detect, nothing to emit to plans, nothing to gate at merge. The plan schema has a ## Manual Steps (Post-Automation) section but it's author-populated only.

5 Whys

  1. Prod broke — middleware queried a column that didn't exist.
  2. Migrations never ran — migrations 022–025 never applied to Supabase.
  3. Manual application is the deploy model — per project's supabase/CLAUDE.md.
  4. No skill surfaced the manual step — not at plan time, execute time, or finish time.
  5. The concept doesn't exist — "manual-deploy artifact" isn't a type the plugin reasons about.

Generalization — 10 artifact classes

Not migration-specific. Same failure mode for:

DB migrations

Supabase / Prisma / Drizzle — column or table missing at runtime.

.env additions

Runtime crash or silent undefined value.

Cron jobs

Silently never runs.

Feature flags

Feature dead on prod or live too early.

Webhooks / OAuth

Vendor 4xx/5xx, silent drops.

DNS / domains

DNS_NOTFOUND, cert failure.

Edge functions

URL 404s at runtime.

RLS policies

403 / file-not-found.

Queues / topics

Messages dropped.

Secrets / API keys

Runtime crash in prod only.

v1 ships 2 of these: Supabase migrations (the one that bit you) and env vars. Structure supports incremental expansion.

4a · Foundation: skills/_shared/manual-deploy-artifact-catalog.md

Prose markdown per-entry, matching deployment-pitfall-catalog.md. LLM-loaded via Read. Small fenced blocks inside each entry carry the 3 machine-matchable fields so enforcement is literal, not interpreted.

Why prose, not YAML Architect confirmed: zero _shared/ files use YAML-structured entries. Every _shared/ file is LLM-loaded reference, not parsed data. A YAML schema would break pattern match with maintainers who have internalized the existing two catalogs.

4b · writing-plans auto-populates the plan

  • New step before the Critique Panel: Manual Deploy Artifact Scan.
  • Walks planned Create: and Modify: paths.
  • For each catalog match not in built-in exempt patterns (**/seed/**, **/fixtures/**, **/__tests__/**, **/*.test.*), injects an entry into ## Manual Steps (Post-Automation).

Why writing-plans is root layer First point where concrete file paths exist. The plan is the durable artifact the user re-reads a week later. Upstream (brainstorming) is too abstract; downstream arrives after "code shipped = done" mental model has set.

Ledger (shared-migration dedup)

At docs/plans/.manual-deploy-ledger.md, append-only: {file-hash} {date} {branch} {project-ref}. Lookup matches on hash + project-ref, not hash alone — prevents false-skip when two projects coincidentally share a migration hash.

M1: Supabase Migration CRITICAL

Why manual deploy: Supabase projects using the SQL Editor workflow require each migration to be applied by hand in the target environment. Unapplied migrations mean prod code depends on schema that doesn't exist.

Detection: New files under supabase/migrations/*.sql in branch diff, excluding built-in exempt patterns.

# Machine-matchable fields (per catalog schema header)
detector_glob: "supabase/migrations/*.sql"
severity: CRITICAL
evidence:
  recommended: sql-editor-url        # genuinely non-synthesizable
  fallback_a: sha256-hash             # reduces reflexive-yes
  fallback_b: echoed-sql-substring    # reduces reflexive-yes
  url_template: "https://supabase\\.com/dashboard/project/[a-z0-9]+/sql/[0-9a-f-]+"
  project_ref_capture: "/project/(?P<ref>[a-z0-9]+)/sql/"

Prod step (plan entry): "Apply each migration below via the Supabase SQL Editor in the production project. Paste the Success output back into this section when done."

M2: Environment Variable Addition MEDIUM

Why manual deploy: New process.env.FOO references require the value to be set in the hosting provider dashboard. Silent undefined or runtime crash if missed.

Detection: New process.env.X references not in .env.example; diff on .env.example.

detector_glob: ".env.example"
detector_grep: "process\\.env\\.[A-Z_]+"
severity: MEDIUM
evidence:
  kind: typed-confirmation
  template: "Type each new variable name and confirm
    the value is set in the production hosting
    provider dashboard"

Prod step (plan entry): "Set each variable below in the production hosting provider dashboard. Type the variable names back into this section after confirming."

  • **/fixtures/** — test fixtures
  • **/__tests__/** — test code
  • **/*.test.* — test files

Cross-cutting integration risks

Eval surface must be updated together SKILL.md edits to writing-plans and finishing-a-development-branch change LLM behavior surface. e2e/ pytest chain enforces: source → eval-surface.yaml → trigger-map.yaml → scenario YAML. If any hop is missing, CI fails. Task 7 in the plan handles this.
Plan-write idempotency Step 0.5 writes evidence to the plan file. Re-running the skill must not duplicate evidence entries or corrupt the plan. Needs explicit test coverage.
Plugin split coupling Feature spans writing-plans + finishing-a-development-branch + _shared/. All destined for aligned-works plugin per the in-flight split. Recommendation: land before the split — one PR scope, fewer coordination costs.
False-positive cost vs. false-negative cost Built-in exemption patterns are conservative (**/seed/**, **/fixtures/**). False positive = friction; false negative = production outage. Err toward friction in doubt.

Known v1 gaps (accepted, not blockers)

  • (a) Projects with CI-automated migrations will false-positive per branch — v2 candidate for root CLAUDE.md opt-out.
  • (b) Ledger is per-repo, not shared across clones — two developers on different machines do not share skip-state.
  • (c) Reflexive-yes only partially prevented. Only M1 kind (a) (SQL Editor URL) is genuinely non-synthesizable. Kinds (b) and (c) are computable from the local repo. v2 candidate: Supabase API verification.
  • (d) M2 env vars similarly partial — v2 candidate: hosting provider API readback.
  • (e) Cross-skill authorship exception creates a bidirectional file-reference (Round 2 QA N3). Task 13 adds a grep CI check. Plugin-split (§4f) must update both files atomically.
