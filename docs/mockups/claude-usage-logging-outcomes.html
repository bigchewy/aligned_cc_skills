Claude Code Usage Logging — Outcomes

Business-mode brainstorm output · 2026-04-23 · Architect-consulted · 4-critic panel reviewed (Round 1 + Round 2)

Paired with the frozen technical design. Defines what friction the logger catches, what the Monday digest drives, and how infrastructure ships in phases by outcome value rather than technical ease.

Goal Detect deviations from Eric's stated and implicit expectations of Claude — surface them weekly with enough context to act — so Eric tunes config and rules structurally instead of re-correcting every session.

Diagnosis (3-why drill-down)

Why do rule violations, drift, and fabrication keep happening?

  1. Claude reads CLAUDE.md at session start but treats rules as advisory prose, not structural constraints.
  2. Prose has no per-turn enforcement mechanism — no compilation check, no required tool call, no test.
  3. The ephemeral textual medium (chat) has no structural affordance for promoting a violation into a persistent rule that binds the next turn.
  4. Asymmetry between correction cost (user-borne, per session) and rule-writing cost (user-borne, per lifetime). Correcting in the moment is the path of least resistance; formalizing into a rule gets deferred indefinitely.

Why do skill-invocation misses, abandonment, and context-skipping keep happening?

  1. Claude's system prompt has no pre-action checkpoint forcing "what skill/sub-agent/prior-doc applies?" before acting.
  2. From Claude's side, pausing to survey has immediate token+latency cost; acting wrong has deferred cost (user absorbs via correction).
  3. Asymmetric cost of wrong-action vs pause-and-verify favors action. Correction events don't feed back into Claude's pre-action routines.

Guiding policy

Close the cost asymmetry in two places:

+ At emission time: behavioral protocols (mode-echo, cite-or-uncertain, <!-- DECISION-LOG -->, survey-first) shift cost to before Claude acts

+ At promotion time: deterministic rule-compliance scoreboard + structured copy-paste digest makes rule-writing cheap enough to happen weekly rather than never

Monday 1 tests whether protocols alone are sufficient. If Tier-A violations drop week over week with only protocols, the digest layer becomes optional.

Source of power

Deterministic rule-compliance scoring against Eric's CLAUDE.md corpus — articulate, current, hand-written. No off-the-shelf logger knows his rules.

+ Tier A (directly detectable via substring/regex): banned phrases, required tool patterns, commit conventions

+ Tier B (indirect via behavioral proxies): "root cause first" → RCA-invoked before Edit

− Tier C (rhetorical quality, architectural taste): out of scope for automated scoring; spot-check only

Exact A/B/C distribution measured empirically at Week 0, not claimed up front.

Five friction classes (phased by evidence)

Ranked by evidence strength and detection tractability. Only classes 1 and 3 ship in the first month; classes 2, 4, 5 deferred until the first two produce operational data.

1. Expectation deviation Action A · Monday 1

Rule violations + corrections for expectations not yet written as rules. Mode drift, fabrication, banned-phrase slips.

Detect: Tier-A scoring (Monday 1) + correction-parse + Tier-B phased weekly

2. Scaffolding bypass Deferred → Monday 8+

Skill / sub-agent / prior-context not used when it should have been. Parallel track: skill-auto-router worktree.

3. Config gap Action C · Monday 4

Permission prompts an allow-list could have covered. Config incomplete, not ignored.

Detect: auto-approve-* hook decision log

4. Decision conflict Deferred → Monday 8+

Protocol ships Monday 1; class-4 detection waits for sample quality ≥ 7/10 real across 2-week window.

5. Skill/agent health Separate channel

Several skills exceed 300 lines (finishing-branch 657, writing-plans 522, RCA 390). Adaptive-interval audit (clean=7d / issues=4d). [SKILL HEALTH] tag, not weekly digest.

Cross-cutting mechanism: user-correction event detection Widened phrase list with 3 confidence tiers. High (0.9): "I thought you'd…", "you're supposed to…", "you stopped…". Medium (0.6): "no,", "wait,", "stop", "undo", "that's wrong", "hang on". Low (0.3): "actually", "hmm" — logged but suppressed from digest rows. Weekly 20-correction calibration sample tunes the phrase list.

The two-layer system

Behavioral protocols force Claude to externalize intentions mid-session. Hooks capture signals. Digest aggregates weekly. Monday actions update config. Config shapes next week's sessions. Loop closes.

Design principle for phasing Each Monday ships only what the previous Monday's evidence justifies. Monday 1 is a falsification setup: if it fails, Monday 4 doesn't ship. Progressive disclosure keeps cognitive load bounded and avoids over-building against an unvalidated value hypothesis.

Kill criteria — six triggers, any one fires retirement

Each layer extends the guard one step beyond the ritual. The sixth catches the case where all five upstream layers can't fire because their inputs are dormant.

  • Tier-A violation count flat or rising at Week 8 (core value hypothesis failed)
  • Digest unread 3+ consecutive Mondays (drift detector fires repeatedly)
  • Correction-parse false-positive rate > 40% after 4 weeks of calibration (signal too noisy)
  • Protocol-compliance spot-check < 30% at Week 8 (Claude isn't following protocols; machine has no inputs)
  • Decision-trail real rate < 40% at Week 8 (Claude fabricating markers)
  • [QA STALE] tag fires 3+ consecutive weeks and isn't acted on (measurement itself has gone dormant)
Retirement is explicit, not silent If a kill criterion fires, the next Monday's artifact is a one-page learning memo, not a digest: what hypothesis failed, what we can take into the next system, what was worth the investment regardless. Framing is "we learned X," not "we failed at Y." The system's retirement is itself a data point, not a shame surface.
