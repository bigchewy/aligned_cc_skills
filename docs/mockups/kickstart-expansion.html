Phase 1: Project Type Selection NEW

Before gathering any other context, the skill presents a type selection prompt. The chosen type determines the scaffold path, context questions, and CLAUDE.md template. No auto-detection — explicit user choice every time (Decision #1).

  • Software — code, tests, builds. Full scaffold with e2e/, eslint-rules/, tech stack questions.
  • Business — consulting, clients, deliverables. Flat structure, placeholder guardrails for confidentiality.
  • Personal — knowledge management, life domains. Flat structure, privacy-focused guardrails.
  • General — anything else that needs structure. Minimal scaffold, empty placeholders.

Phase 2: Gather Context MODIFIED

Context gathering now branches by project type. All types share a common base of two questions. Software adds three more; non-technical types skip them entirely.

  • All types ask: Project name + one-sentence description, additional context (linked via @ symbol)
  • Software additionally asks: Tech stack (default: Next.js + TypeScript + Tailwind), deployment platform (default: Vercel), testing framework (default: Jest/Vitest/pytest)
  • Business, Personal, General: Skip tech-specific questions 3-5 completely

Phase 4: Seed CLAUDE.md MODIFIED

All templates share a consistent 6-section structure (Decision #7). Content varies by type: software gets fully populated sections, business pre-seeds workflow triggers for the business skill pipeline, and personal/general get lean placeholders with hints (Decision #8). All reading priority sections reference ~/.claude/about-me.md (Decision #3).

  • Section 1 — Project Identity: What this is, who it's for
  • Section 2 — Folder Map: Where files go, naming conventions
  • Section 3 — Reading Priority: What Claude should front-load (always includes about-me.md)
  • Section 4 — Communication Preferences: Output style, tone, format
  • Section 5 — Guardrails: Sensitivity, privacy, constraints
  • Section 6 — Workflows: Skill/agent triggers

Software Template RESTRUCTURED

The existing software template, restructured into the 6-section format. Adds a new ~/.claude/about-me.md reference in reading priority. All sections are fully populated with project-specific content derived from context gathering.

  • Identity: Project overview, tech stack
  • Folder Map: Full directory structure (docs/, e2e/, scripts/, etc.), file locations
  • Reading Priority: CLAUDE.md → ~/.claude/about-me.md → docs/architecture.md
  • Communication: Commands section (test, build, lint, dev)
  • Guardrails: Iron Rules (TDD, error path tests, verify before claiming, root cause first)
  • Workflows: All skill invocations (brainstorming, writing-plans, executing-plans, finishing-a-development-branch, systematic-debugging, design-principles, eval-failure-triage, eval-audit)

Phase 5: Global About-Me Check NEW

After scaffolding, the skill checks whether ~/.claude/about-me.md exists. Named about-me.md (not profile.md) to avoid collision with the existing claude-profile skill which handles account switching (Decision #3). Creates ~/.claude/ first if the directory doesn't exist. Gracefully skips with a note on permission failure.

  • If about-me exists: No action. CLAUDE.md templates already reference it via reading priority.
  • If about-me missing: Ask "No global about-me found at ~/.claude/about-me.md. Want to create one now?"
  • Template sections: Role & Identity, Expertise, Methodology, Communication Style
  • Optionally suggest adding a reading priority reference to ~/.claude/CLAUDE.md (with confirmation — do not modify without it)
  • Permission failure: If ~/.claude/ cannot be created, skip with a note and continue scaffolding
