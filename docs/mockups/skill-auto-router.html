Skill Auto-Router

Problem-first routing with framework cascade for the Aligned plugin

Automatic skill and framework routing so non-technical users never need to learn slash commands. Install the plugin, and Claude Code is just better. Post-critique revision reflecting precision gates, exclusion patterns, error recovery, and telemetry.

End-to-End Routing Flow

User prompt enters the hook, passes through a cascade of matchers, and either routes to a skill/framework or passes through to Claude natively. Default fallback is pass-through (no intervention), not brainstorming. All skill routes require min_signals: 2.

Measurement Method

  • Test corpus — 50+ prompts sourced from actual user sessions and the plugin creator's own usage, each labeled with the correct route (specific framework, specific skill, or pass-through)
  • Precision — of prompts where the router fires, how often it picks the correct route. Measured by running the corpus through the router and comparing against labels
  • False positive rate — of prompts labeled "pass-through," how many trigger routing intervention
  • Override rate — tracked via telemetry in production. "Skip" events and redirects divided by total router activations

Hook ArchitectureUserPromptSubmit

A UserPromptSubmit hook intercepts every user message and runs lightweight, rule-based classification. No external API calls at runtime. The hook reads a precomputed routing index and appends directives that Claude sees but the user does not.

  • Hook entry point — hooks/skill-router.sh or .js fires on every user prompt submission
  • Routing index — skill-router.json contains precomputed framework triggers, skill signal patterns, and exclusion patterns
  • Build-time generation — scripts/build-router-index.js uses LLM to extract intent phrases from framework content
  • Zero runtime dependencies — no embedding calls, no API calls, just string matching against the index
  • Invisible intervention — directives are appended to the prompt; the user sees framework suggestions, not routing machinery
  • Telemetry logging — routing decisions, overrides, and fall-throughs logged to a local file for threshold iteration

Build PipelineDeveloper-Only

The routing index is generated at build time by a developer script, not at runtime by end users. Framework content is processed through an LLM to extract high-quality intent phrases.

  • Input — walks framework directories, reads each framework's metadata and content
  • LLM extraction — generates intent phrases and trigger terms from framework descriptions
  • Output — skill-router.json with framework entries, skill signal patterns, and exclusion patterns
  • Trigger — run manually when frameworks are added or modified

Routing Cascade4 Steps

The cascade processes prompts through increasingly general matchers. Each step either routes the prompt or passes it to the next step. Precision over recall — false positives erode trust faster than missed routes. Default fallback is pass-through, not brainstorming.

Step 0 — Skill Invocation BypassHighest Priority

If the prompt contains an explicit skill invocation (/aligned:... or clear intent to use a specific skill), pass through without routing. The user already knows what they want.

  • Detection — regex match on /aligned: prefix or explicit skill names
  • Action — no directive appended, prompt passes through unchanged
  • Rationale — never interfere with intentional invocations

Step 1 — Framework MatchHighest Confidence

Check the prompt against a precomputed index of framework metadata — names, aliases, trigger phrases, intent phrases. Frameworks are high-specificity: anchor terms like "five forces" or "positioning canvas" are unambiguous.

  • Single high-confidence match — present the framework and proceed immediately with a one-line opt-out
  • Multiple plausible matches (2-3) — present options with the recommended one first, plus a freeform fallback
  • No match — proceed to Step 2 (skill classification)

Step 2 — Skill ClassificationMedium Confidence

Keyword/phrase pattern matching against four skill buckets. All skills require min_signals: 2 — at least two signal phrases must match, or one signal plus domain context (prompt >20 words with problem-domain vocabulary). Each skill also defines exclusion patterns that suppress routing even when positive signals match.

  • Diagnose/fix — routes to root-cause-analysis on signals like "why is," "what's causing," "not working." Excludes: "why is the sky," "why is it called"
  • Test content — routes to persona-panel on signals like "test this with," "audience reaction"
  • New project — routes to kickstart on signals like "new project," "scaffold," "from scratch"
  • Build/create — routes to brainstorming on signals like "figure out," "think through," "strategy for." Excludes: "help me plan my," "figure out what to eat"
  • Error recovery — all skill routes include a one-line acknowledgment with opt-out, e.g., "This sounds like a diagnostic problem. I'll help you trace the root cause. Say 'skip' if you'd rather just discuss it."

Step 3 — Below Confidence ThresholdDefault: Pass Through

When no step produces a confident match, the prompt passes through untouched. Claude handles it natively. This is the correct default — routing should only fire with high confidence. When in doubt, do nothing. Brainstorming is not a fallback; it requires min_signals: 2 like every other skill.

  • No directive appended — Claude sees the original prompt only
  • No user-visible change — behaves exactly as if the plugin weren't installed
  • Precision over recall — silence is better than a wrong suggestion for this audience
  • Telemetry logged — fall-through prompts are logged to identify framework gaps over time

Routing Directive FormatInvisible to User

The hook appends a structured directive to the prompt that Claude sees but the user does not. The directive tells Claude which skill or framework to invoke, what to say, and how to proceed. All directives include a one-line acknowledgment with opt-out.

  • Single framework match — present the framework, offer an opt-out, then invoke use-framework
  • Multiple framework matches — present numbered options with a freeform fallback
  • Skill match (no framework) — acknowledge the intent, offer opt-out, then invoke the skill

Single Framework Directive

[ALIGNED-ROUTER] A framework matches this request. Present it to the user and proceed: - Framework: "Porter's Five Forces" (advisor: michael-porter) - Say: "This looks like a competitive analysis problem. I'll walk you through Porter's Five Forces to structure your thinking. Just say 'skip' if you'd rather go freeform." - Then: Use Skill(aligned:use-framework) with framework "porters-five-forces"

Multiple Framework Directive

[ALIGNED-ROUTER] Multiple frameworks may apply. Present options and let the user choose: - Option 1: "Positioning Canvas" — clarifies differentiation (advisor: april-dunford) - Option 2: "Porter's Five Forces" — maps competitive dynamics (advisor: michael-porter) - Option 3: "Value Metric" — examines pricing alignment (advisor: madhavan-ramanujam) - Fallback: "Or just talk it through freeform" - Then: Use Skill(aligned:use-framework) with their choice, or Use Skill(aligned:brainstorming) for freeform

Skill-Only DirectiveUpdated: Opt-Out Added

[ALIGNED-ROUTER] No framework match, but intent is clear. - Intent: diagnose/fix - Say: "This sounds like a diagnostic problem. I'll help you trace the root cause. Say 'skip' if you'd rather just discuss it." - Then: Use Skill(aligned:root-cause-analysis)

Routing Index Structureskill-router.json

A static JSON file that ships with the plugin. Two sections: frameworks (array of framework entries with triggers and intent phrases) and skills (object with signal patterns, exclusion patterns, and thresholds). Generated by the build script, not hand-edited.

  • Framework entries — id, name, advisor, trigger terms (exact matches), and intent phrases (semantic phrases)
  • Skill entries — signal patterns, exclusion patterns, min_signals: 2 for all skills
  • 138 frameworks indexed with high-specificity anchor terms (easier to match than 6 overlapping skills)
  • Coverage gap — current ~50% of common business tasks; deep in positioning/marketing, gaps in finance/HR/ops

Framework Entry Schema

{ "id": "porters-five-forces", "name": "Porter's Five Forces", "advisor": "michael-porter", "triggers": ["porter", "five forces", "competitive forces"], "intent_phrases": [ "competitive landscape", "industry analysis", "competitive threats", "market competition" ] }

Skill Entry SchemaUpdated: Exclusions + min_signals: 2

{ "root-cause-analysis": { "signals": ["why is", "why are", "what's causing", "root cause", "keeps happening", "not working", "failing", "broken", "declining"], "exclude": ["why is the sky", "why is it called", "why is there"], "min_signals": 2 }, "brainstorming": { "signals": ["figure out", "think through", "strategy for", "how should I", "help me plan", "design a", "what's the best way to"], "exclude": ["help me plan my", "figure out what to eat", "think through my schedule"], "min_signals": 2 } }

User Experience Examples5 Scenarios

Real-world prompt examples showing how the router responds across the confidence spectrum. The north star: install the plugin, and Claude Code is just better. No training required. All skill routes now include a one-line opt-out, matching the framework interaction pattern.

Example 1: Single Framework Match

User types: "I need to figure out how to position our product against cheaper competitors."

  • Router matches — Positioning Canvas (high confidence via "position" trigger)
  • User sees — "This looks like a positioning problem. I'll walk you through the Positioning Canvas to clarify your differentiation. Just say 'skip' if you'd rather go freeform."
  • Result — proceeds into Positioning Canvas framework with April Dunford advisor

Example 2: Multiple Framework Match

User types: "We're losing enterprise deals to a competitor who's undercutting us on price."

  • Router matches — Positioning Canvas, Porter's Five Forces, Value Metric
  • User sees — numbered options with the most relevant first, plus freeform fallback
  • Result — user picks one, enters that framework

Example 3: Skill Match (No Framework)Updated: Opt-Out

User types: "Our onboarding process is a mess and new hires keep quitting in the first 90 days."

  • Router matches — no framework (HR coverage gap), but intent is "diagnose/fix" (signals: "mess" + "keep quitting" meet min_signals: 2)
  • User sees — "This sounds like a diagnostic problem. I'll help you trace the root cause. Say 'skip' if you'd rather just discuss it."
  • Gap identified — HR frameworks needed; tracked via telemetry for future framework gap-fill initiative

Example 4: No Match (Pass Through)

User types: "Summarize this document for me."

  • Router matches — nothing above threshold (zero signals matched)
  • User sees — Claude handles it natively, no intervention
  • Result — behaves exactly as if the plugin weren't installed. Fall-through logged to telemetry

Example 5: Explicit Invocation (Bypass)

User types: "/aligned:brainstorming I want to redesign our pricing page."

  • Router detects — explicit /aligned: prefix
  • User sees — brainstorming skill activates normally, zero router interference

Deliverables5 Items

Five concrete deliverables to ship the auto-router. Framework gap-fill is a separate initiative, triggered by telemetry data.

  • Hook script — hooks/skill-router.sh or .js, the UserPromptSubmit hook with matching logic
  • Routing index — skill-router.json, precomputed framework and skill matching rules including exclusion patterns
  • Build script — scripts/build-router-index.js, generates the index from framework content via LLM
  • Test corpus — 50+ real user prompts, each labeled with the correct route (framework, skill, or pass-through)
  • Telemetry logging — local file logging of routing decisions, confidence levels, user overrides, and fall-throughs

Separate InitiativesOut of Scope

  • Business task taxonomy — 15-20 common business task categories for the primary persona. Used to measure coverage and prioritize gap-fill
  • Framework gap-fill — new frameworks for underserved categories. Triggered by router telemetry showing which prompts fall through most often, not by upfront estimation
